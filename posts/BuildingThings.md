I'm a final-year university student, and my projects have taken me from Android apps and backend services to embedded devices and local AI tools. I usually start with a problem I'm interested in, then learn what I need to get something working.

Here's a look at what I've been building and how those interests fit together.

## Apps and networking

With Mizuki, I've been working on native Android development using Kotlin, Jetpack Compose, and Material 3. In paperand, I take a different route with React Native and Expo for a cross-platform app.

Anis gets closer to the network itself: it's a local DNS sinkhole and per-application firewall. Working on these projects means moving between what someone sees on screen and what their device is doing underneath.

## Go, APIs, and Discord bots

Go comes up a lot in my backend work. vngasprice turns public fuel-price data into a REST API. phatnguoicheck-go handles traffic-violation lookups, bringing together scraping, parsing, OCR, retries, and an API layer.

I also build things around communities and tools I use. HoYo Code Sender distributes HoYoverse redemption codes through Discord. It has grown to include server configuration, multilingual support, a web dashboard, livestream tracking, and persistent storage.

## Local AI tools

More recently, I've been experimenting with local AI workflows through manga-trans. It combines an MCP server, local OCR, image processing, inpainting, automated typesetting, pixel-level checks, and a web studio for manga localization.

I'm interested in how those pieces work together. A model can handle reasoning, while ordinary code takes care of predictable processing. Keeping those responsibilities separate makes it easier for me to understand what's happening at each step.

## The hardware side

I also work with ESP32, Arduino, embedded Linux, sensors, and communication interfaces. I like seeing how application code connects to the physical device, especially when I need to follow a problem through the network, operating system, and hardware to understand it.

## What I'm working toward

These projects give me different things to learn, but I'm still a student preparing for an internship. I want to get better at the engineering behind the working prototype: understanding my tools more deeply and making the software I build more dependable.
